# Решения, границы и демонстрация

## Идея и отличие

«У меня есть 35 минут — куда выйти и успеть вернуться?» Qadam даёт небольшую прогулку с понятной причиной выбора и источниками. Контекст проверяется до генерации объяснения; расстояния учитывают дорожную сеть; факты отделены от предложенных занятий. Это свойства реализации, а не обещание превосходства над всеми конкурентами.

## RAG и планирование

`Overpass → нормализация/дедупликация → POI snapshot → retrieval → ограничения + OSM graph → план с возвратом → Gemini → validation → UI`

- Автосбор сохраняет теги, источники, timestamp и provenance. Неизвестные часы, indoor и wheelchair не заполняются догадками.
- Retrieval использует категории/слова RU/KK/EN и теги; векторной базы и embeddings в MVP нет. Shortlist ограничен 18 кандидатами с сохранением разных категорий.
- Граф: CSR, Dijkstra с binary heap, поисковые деревья принадлежат текущей сессии. В сетевом режиме остановки добавляются жадно; при геометрической оценке перебираются короткие варианты shortlist. Глобальная оптимальность по всему городу не гарантируется.
- План включает все участки, возвращение, посещение и запас 8% бюджета в пределах 3–10 минут. Длительности посещения — продуктовые эвристики, не сведения заведений. Часы проверяются на весь визит.
- Gemini получает query, язык и выбранные POI. Генерируются только summary/why/activity. Валидатор проверяет ID, порядок, дубли, тип/длину текста, HTML, числовые утверждения и URL. При ошибке исходный план сохраняется в retrieval-режиме.
- Эта проверка не доказывает семантическую истинность каждой фразы LLM. Исходные поля остаются отдельными; предлагаемые занятия помечены как идеи.

## Границы и риски

890 POI, 81 383 узла, 97 427 рёбер покрывают центральную Астану. Данные OSM могут быть устаревшими. У 774 POI нет часов; у 882 indoor неизвестен; 8 явных indoor-записей — детские площадки. Строгий фильтр вправе вернуть пустой результат.

Узлы/рёбра реальны, но пути не проверены в поле. Соединения до узла ≤200 м оцениваются по прямой; POI-центр может отличаться от входа. Скорость 70 м/мин фиксирована. При отсутствии сети fallback — прямая ×1,35; известный длинный сетевой путь им не сокращается. Исключение лестниц и wheelchair-тег не подтверждают пандусы, бордюры, покрытие и безопасность всей прогулки.

Погода, снег, события, билеты, цены, рейтинги, групповые предпочтения и индивидуальная скорость в MVP не рассчитываются. Сложные условия естественного языка не поддерживаются универсально; используйте явные фильтры.

## Приватность и бизнес-гипотеза

Код не пишет историю запросов/координат в БД, localStorage или sessionStorage. Точный старт нужен серверу для текущего расчёта. Хостинг/Cloudflare обрабатывает запрос; OSM получает запросы тайлов области. В Gemini payload нет отдельного origin/координат старта: отправляются query, язык и выбранные POI. Личные сведения, введённые самим пользователем в query, автоматически не удаляются и могут попасть провайдеру. Его технические журналы приложение не контролирует. Ключ — только на сервере, вне Git/архива/видео.

Возможное развитие — пилот с кампусом или турцентром; это гипотеза, не действующее партнёрство. Монетизация и платное ранжирование не реализованы. Коммерческое продвижение в будущем должно быть явно обозначено.

## Следующие шаги

1. Полевой прогон маршрутов; официальные часы и входы с источником/датой проверки каждого поля.
2. Данные переходов, барьеров, бордюров и покрытия; проверка с пользователями с ограничениями мобильности.
3. Размеченные запросы для оценки релевантности и фактологических ошибок; сравнение retrieval с embeddings.
4. Проверяемые события, группы, адаптивная скорость; устойчивый источник данных/тайлов для масштабирования.

| Время | Содержание |

| 0:40–1:15 | Пользователь, 1–3 места, контекст, источники |
| 1:15–2:45 | Живое демо по сценарию ниже |
| 2:45–3:45 | Автосбор → retrieval → граф/ограничения → ограниченная генерация |
| 3:45–4:45 | 61 тест: 38 unit + 23 extended, включая 21 реальный сценарий; missing data и честный fallback; [фактические результаты](EVALUATION.md), без непроведённых benchmark-оценок |
| 4:45–6:00 | Польза для кампуса/города, гипотеза пилота, приватность, риски, roadmap |

## Демо на 90 секунд

| Время | Действие |
|---|---|
| 0–15 с | «Пауза между парами»: Байтерек, кофе, 35 минут |
| 15–35 с | Показать реальный план, линию, дорогу/посещение/запас и возврат. Назвать фактический режим Gemini/retrieval |
| 35–50 с | Уменьшить бюджет до 20 минут; показать перерасчёт либо честный пустой результат |
| 50–65 с | Открыть источник: факты из OSM, unknown-часы, занятие как идея |
| 65–80 с | Включить известное расписание: пропуски данных не превращаются в обещание «открыто сейчас» |
| 80–90 с | Показать trace: как найдены места, посчитано время и сформировано объяснение |

Перед записью прогнать сценарий на актуальном времени. Не обещать заранее конкретную точку и не заменять живой результат макетом.
