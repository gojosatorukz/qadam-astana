# Qadam v4: проверка и границы выводов

Здесь разделены три разных результата: автоматические инварианты кода, replay с заданным oracle-контрактом и реальные ответы Gemini. Ни прохождение тестов, ни oracle replay не являются измерением точности модели.

Все запросы оценочного набора составлены для проверки и используют публичные стартовые точки интерфейса. Личных GPS-треков, пользовательских аккаунтов, ключей и запросов реальных пользователей в публичных артефактах нет. POI и OSM ID публичные. [Исходные evidence и правила чтения](evaluation/README.md).

## 1. Чистая установка и код

20 октября 2026, Asia/Almaty, создан отдельный checkout без `.env*`, ключей, старых `node_modules`, `dist` и runtime. Node **24.12.0**, npm **11.6.2**. Обычный `npm ci` из официального registry установил **688 пакетов за 34 секунды**, exit 0; lockfile не изменился. Скопирован один публичный snapshot и затем только явно разрешённые финальные изменения UI. Основные зависимости и lockfile проекта не трогались.

```sh
npm ci
npx tsc --noEmit --incremental false
node --experimental-strip-types --test tests/*.test.ts
```

**Фактически: TypeScript без диагностик; 167/167 тестов, 0 ошибок, пропусков и отмен.** В этот итог уже входят:

- Unit/regression-проверки бюджета и возврата, часов с секундами, источников/ID, графа, strict filters, отрицаний RU/KK/EN, authoritative intent, all/any и уточнения.
- Прежние **21 сценарий на реальном снимке**, provenance и повторяемость. Новые unit-тесты не объявляются дополнительными полевыми маршрутами.
- **30 oracle integration** production pipeline, описанные ниже.
- Подменённые ответы провайдера, таймауты fetch/body без соблюдения AbortSignal, общий deadline и закрытая схема кодов generation. Это проверка обработки ответов, не новых реальных вызовов Gemini.

Полный локальный тестовый запуск занял около 2,6 секунды на проверочной машине; это не latency опубликованного API. После последних UI-правок TypeScript проверен повторно. [Санитизированный журнал clean install](evaluation/clean-install.txt).

**No-key HTTP smoke: 8/8 проверок.** Health вернул `geminiConfigured=false`, 890 POI и 81 383 узла. Пустой query + ручное кафе → `manual/matched`, маршрут `walking`, **39 = 10 пути + 25 посещения + 4 запаса**, включая **5 минут обратно**. Текст на RU/KK/EN без ключа → `unavailable/not-configured`, `needs-clarification`, `plan=null`. Те же ручные настройки при 20 минутах → `empty`; `now` без timezone → HTTP 400; HTML приложения → HTTP 200. Сервер после проверки остановлен. Это реальный HTTP smoke, не browser E2E и не проверка доступности облачной модели.

## 2. Oracle replay — инварианты, не AI accuracy

[replay-contract.v1.json](evaluation/replay-contract.v1.json) передаёт в production `buildPlan` заранее заданные, независимо замороженные gold-контракты. Планировщик, feedback, реальные POI и граф работают; интерпретатор подменён oracle, обогащение — identity. **Cloud calls = 0**. Поле `mode=gemini` в replay — симулированная метка транспорта, не доказательство вызова модели.

**30/30 случаев соблюли инварианты:** запреты, бюджет, возврат, отсутствие подмены музейного текста default coffee chip, корректные unsupported/clarification. Получены 20 `matched`, 4 `partial`, 4 `empty`, 2 `needs-clarification`. Неполный маршрут не исправляется вымышленным POI или ослаблением фильтров. Эти 30 случаев также входят в общие 167 тестов; суммировать их повторно нельзя.

## 3. Реальная интерпретация Gemini — один замороженный прогон

[Gold](evaluation/gold.v1.json): 30 выбранных запросов, по 10 RU/KK/EN. Ожидания и compatibility mapping к закрытому контракту зафиксированы до реализации и новых вызовов. Сохранённый legacy baseline дал **7/30** строгих совпадений на том же выбранном gold; это старый детерминированный parser без cloud-вызовов. [Baseline](evaluation/baseline-summary.v1.json).

Финальный prompt/schema/validator заморожены перед единственным прогоном v4; повторов и правок по ходу не было. Модель `gemini-3.5-flash-lite`, лимит интерпретации 6000 мс; случаи шли последовательно с паузой в секунду. [Freeze](evaluation/final-intent-freeze.v4.json) · [полный результат](evaluation/final-intent-thirty.v4.json) · [анализ](evaluation/final-analysis.v4.txt).

| Срез | Строгие совпадения | Реальные API-вызовы / ручные случаи |
|---|---:|---:|
| Все выбранные случаи | **26/30** | **27 / 3** |
| Только API | 23/27 | 27 / 0 |
| Ручные пустые запросы | 3/3 | 0 / 3 |
| 9 случаев, использованных при разработке | 6/9 | 9 / 0 |
| 21 впервые отправленный этому intent-провайдеру случай | 20/21 | 18 / 3 |
| API-only внутри first-seen 21 | 17/18 | 18 / 0 |

Strict match требует совпадения наборов desired/excluded, all/any, уточнения и точных цитат unsupported с причиной по замороженному mapped gold. Сравнение **26/30 против 7/30** — наблюдение на одном выбранном наборе; это не общая accuracy и не пользовательский benchmark. Девять примеров уже использовались при разработке. First-seen21 означает, что эти ID ранее не отправлялись этому intent-провайдеру; предметная область и закрытые категории были известны, так что это не независимый внешний benchmark. В first-seen 21 есть три ручных случая, поэтому корректно показывать также API-only17/18.

**Четыре несовпадения сохранены как ошибки:**

- **RU03:** желаемый парк и запрет кафе верны, но поддерживаемая прогулка на природе дополнительно объявлена `not-supported`. Это лишнее семантическое ограничение, а не косметическая разница цитирования.
- **KK08:** категория и no-data верны; все четыре атрибута буквально покрыты, но Wi-Fi и розетки объединены в более длинную цитату вместо точных gold-фрагментов. Strict match не пройден.
- **EN09 и EN10:** HTTP **429**, контракт не получен. Оба остаются в знаменателе, не заменяются ручной догадкой и не повторялись для получения успеха.

Две последовательные429 были последними двумя случаями. Stop rule сработал на случае 30: все 30 были предприняты; поле `stoppedEarly` в JSON обозначает триггер остановки, а не пропущенные оставшиеся случаи. После него вызовов не было. Всего в финальном прогоне 27 API-вызовов, не 30. Предшествующая разработка использовала ещё 21 вызов; суммарно 48, не 51.

## Границы результата

Сохраняются 1–3 уникальных исходных POI, возврат к старту, `walking = transitions + return`, `total = walking + visits + buffer ≤ budget`. Unknown не становится open; strict filters требуют подтверждений. Наличие строки расписания не подтверждает фактическую работу двери. Праздники, сезонные и сложные форматы остаются unknown.

`walking` использует собранную сеть, но привязки до 200 м и входы не проверены. При отсутствии покрытия — явный estimate; известный слишком длинный сетевой путь не сокращается им. Wheelchair-тег и исключение лестниц не сертифицируют весь путь. Скорость 4,2 км/ч и длительности — предположения; фактическое прибытие не гарантируется. Выбор остановок — ограниченная эвристика, не глобальный оптимум.

Удовлетворённость пользователей, безопасность в поле, свежесть всех часов и общая языковая точность не измерены. Честное уточнение, partial и empty считаются продуктовым поведением; они не превращаются в strict success, если модель не совпала с gold. Следующие проверки — новые независимо размеченные запросы и реальные прогулки с пользователями.
