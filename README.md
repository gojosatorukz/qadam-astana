# Qadam — короткая прогулка по Астане

Qadam подбирает 1–3 реальных места под интересы и свободное время. Расчёт включает переходы, посещение, возвращение к старту и запас. Пользователь видит, как понят запрос, что удалось включить и каких сведений нет.

## Запуск

Полный исходный код с иерархией каталогов находится в **[qadam-source.zip](qadam-source.zip)**. Скачайте и распакуйте архив, затем откройте полученную папку в терминале. Документация также доступна прямо в репозитории.

Нужны Node.js ≥22.13 и npm:

```sh
npm ci
npm run dev
```

Откройте адрес из вывода сервера; локально обычно `http://localhost:5173`. Стек: React, TypeScript, Vinext/Vite, серверный API на Cloudflare Workers.

Для Gemini задайте серверную переменную `GEMINI_API_KEY` через окружение или `.env.local`. [.env.example](.env.example) содержит пустой шаблон. Модель по умолчанию — `gemini-3.5-flash-lite`; настройка — `GEMINI_MODEL`. Дополнительные проверенные модели обогащения можно явно перечислить в `GEMINI_FALLBACK_MODELS`. Ключ не должен попадать в браузер, Git или архив.

## Как работает v4

- **Пустой текст:** категории из кнопок работают в ручном режиме без ключа и без вызова модели интерпретации.
- **Текстовый запрос:** Gemini возвращает проверяемый intent: желаемые и запрещённые категории, `all/any`, цитаты неподтверждаемых пожеланий, необходимость уточнения. Текст имеет приоритет над исходными кнопками категорий.
- **Нет ключа, таймаут или ошибка интерпретации:** текст не превращается в угаданный маршрут. Интерфейс просит уточнение и предлагает явно перейти к ручному выбору кнопками.
- Код применяет строгие исключения, indoor, расписание и wheelchair, извлекает кандидатов и считает круговой маршрут по графу OSM. Для `all` приоритет — покрыть разные запрошенные категории в пределах бюджета; допустимы честные `partial` и `empty`.
- После расчёта Gemini выбирает только закрытые `reasonKeys`, `activityKey` и `summaryKey`. Код проверяет допустимость для каждой остановки и сам выводит RU/KK/EN-текст. Свободные LLM-утверждения о цене, тишине, Wi-Fi и других неподтверждённых свойствах не выводятся как факты.
- Если второй этап недоступен, уже проверенный маршрут сохраняется с детерминированными пояснениями и явным режимом `retrieval`. Это отличается от сбоя первого этапа, при котором семантический запрос требует уточнения.

Есть четыре публичных старта, геолокация по запросу, готовые сценарии, отправление «Сейчас» / «Завтра, 12:00» с датой, карта, источники и trace. Неизвестные часы остаются `unknown`. Будущая дата не выдаётся за текущее открытие места. Бюджет соблюдается в расчёте, фактическое время прогулки не гарантируется.

```sh
node scripts/collect-pois.mjs              # POI и provenance
node scripts/collect-pois.mjs --graph-only # граф
node scripts/collect-pois.mjs --graph      # оба набора
```

Сбор через Overpass сохраняет теги, источники, timestamp, SHA256 и правила дедупликации в `data/provenance.json`. Описания составлены из фактов источника. Ошибка обновления не заменяет набор пустыми данными; фоновой синхронизации нет. Данные: © OpenStreetMap contributors, [ODbL](https://www.openstreetmap.org/copyright).

## Проверка

```sh
npx tsc --noEmit --incremental false
node --experimental-strip-types --test tests/*.test.ts
```

На чистой установке: **167/167 тестов**, TypeScript без ошибок, HTTP smoke без ключа **8/8**. Включены прежние 21 сценарий на реальном снимке, unit-проверки и 30 интеграционных случаев с заранее заданными oracle-контрактами. Последние проверяют инварианты pipeline, **не точность AI**.

Отдельный замороженный прогон интерпретации: **26/30 строгих совпадений** с размеченным контрактом против **7/30** у сохранённого legacy baseline. Было **27 реальных API-вызовов и 3 ручных случая**; два HTTP 429 включены в ошибки. Из 21 случая, впервые отправленного этому intent-провайдеру, совпало 20/21 (17/18 среди API-вызовов, плюс 3/3 ручных); остальные 9 использовались при разработке. Это один небольшой отобранный набор, не оценка общей точности. [Метод, четыре ошибки и ограничения](docs/EVALUATION.md) · [Публичные артефакты проверки](docs/evaluation/README.md).

Надёжный ручной сценарий без ключа: пустой текст → Набережная Есиля → кофе → 45 минут → известное расписание. На фиксированном снимке: Coffee Original (`24/7` в OSM), 39 минут, включая 5 минут обратно и 4 минуты запаса. При 20 минутах — пусто. Часы источника не подтверждают, что дверь фактически открыта.

## Публикация и ограничения

Канонический адрес: **https://qadam-astana-walk.pubg-bekzat.chatgpt.site**. Sites публикует интерфейс и серверные `/api/places`, `/api/plan` на Cloudflare Workers. GitHub Pages не исполняет серверные маршруты проекта. Повторная публикация сохраняет существующий проект и URL. [Развёртывание](docs/DEPLOYMENT.md).

OSM может быть неполным и устаревшим: у 774 POI нет часов; все 8 подтверждённых indoor-записей — площадки. Wheelchair-тег и исключение лестниц не сертифицируют весь путь. Графовый выбор остановок — ограниченная эвристика; глобальный оптимум не заявляется. Скорость — 4,2 км/ч; соединения с графом до 200 м оценены по прямой и не проверены на препятствия. При отсутствии покрытия используется явно обозначенное расстояние по прямой ×1,35. Это прототип планирования, не официальная навигация.

Код не записывает историю запросов и координат в БД или browser storage. Сервер получает старт для текущего расчёта; структурированные координаты и время отправления не входят в intent payload. На этапе объяснения отправляются query, язык и выбранные POI с допустимыми кодами. Личные сведения, вписанные в query, автоматически не удаляются и могут попасть провайдеру. OSM получает запросы тайлов области; технические журналы внешних провайдеров приложение не контролирует.
